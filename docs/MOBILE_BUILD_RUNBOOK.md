# دليل بناء وتجهيز تطبيق الهاتف ورفعه للمتاجر (Mobile Build & Store Release Runbook)

يوثق هذا الدليل الخطوات التنفيذية التفصيلية لبناء تطبيق المتدرب لمنظومة Z Coaching (`mobile_app`) المبني بإطار عمل Flutter، بدءاً من تجهيز بيئة التطوير، وتوليد الأيقونات وشاشات البداية، مروراً بأوامر التحليل والبناء البرمجي، وصولاً إلى قائمة الاختبارات اليدوية الإلزامية ومعايير الاعتماد على متجري Google Play و Apple App Store.

---

## تنبيه هندسي صريح ومسبق بشأن كود Dart

> **ملاحظة فنية جوهرية**:
> كود تطبيق الهاتف المكتوب بلغة Dart داخل مجلد `mobile_app` تم إعداده وهيكلته معمارياً وربطه بنقاط نهاية الخادم المركزية، ولكنه **لم يُبنَ (Compiled) أو يُشغّل على أي جهاز فعلي أو محاكي حتى الآن**.
> من المتوقع والطبيعي ظهور أخطاء ترجمة برمجية (Compilation Errors أو Type Mismatches أو Dependency Conflicts) عند تنفيذ أول عملية بناء؛ ولذا يتعين على المطور فحصها، وتصحيحها في الكود، وإعادة التحليل حتى يعمل البناء بنجاح تام قبل الانتقال لمرحلة الاختبار والرفع.

---

## 1. متطلبات الجهاز وبيئة العمل (Prerequisites)

### أ. بيئة التطوير الأساسية لكافة الأنظمة
- **حزمة أدوات Flutter SDK**: إصدار متوافق مع متطلبات المشروع (Dart SDK ^3.8.1). يتم تنزيلها وتضمينها في مسار النظام `PATH`.
- **بيئة Android Studio**: لتطوير حزم الأندرويد، مع تثبيت:
  - حزم `Android SDK Platform-Tools` و `Android SDK Command-line Tools`.
  - محاكي أندرويد (Android Emulator) أو جهاز أندرويد حقيقي مفعل عليه وضع تصحيح الأخطاء (USB Debugging).
  - بيئة تشغيل جافا `Java JDK` (الإصدار 17 أو 21 المعتمد من أندرويد ستوديو).

### ب. متطلبات بيئة iOS (حصرية لأجهزة ماك)
- **جهاز حاسوب بنظام macOS**: لا يمكن ترجمة أو بناء تطبيقات iOS أو توقيعها رقمياً على أنظمة Windows أو Linux نهائياً.
- **تطبيق Xcode**: مثبت من متجر تطبيقات Mac App Store مع تنزيل أدوات سطر الأوامر (Command Line Tools).
- **مدير الحزم CocoaPods**: مثبت على نظام ماك عبر الأمر:
  ```bash
  sudo gem install cocoapods
  ```
- **حساب مطور معتمد لدى أبل (Apple Developer Account)**: مطلوب لإعداد شهادات التوقيع الرقمي (Signing Certificates) وملفات التعريف (Provisioning Profiles) ورفع الحزمة على App Store Connect.

### ج. فحص جاهزية البيئة
يتم تشغيل الأمر التالي في سطر الأوامر للتحقق من سلامة كافة الأدوات المساعدة:
```bash
flutter doctor -v
```
يجب التأكد من ظهور علامات النجاح الخضراء أمام أدوات أندرويد وأبل المذكورة أعلاه قبل الشروع في عملية البناء.

## 2. توليد الأيقونات وشاشة البداية من الإعدادات المعتمدة

تم تجهيز إعدادات الأيقونات وشاشة البداية مسبقاً داخل ملف `mobile_app/pubspec.yaml`، وهي تعتمد على ملف الصورة المصدري الموجود في `mobile_app/assets/icon.png`.

لتوليد الأيقونات وشاشة البداية للنظامين، يتم فتح سطر الأوامر والانتقال إلى مجلد التطبيق:
```bash
cd mobile_app
```

### أ. توليد أيقونات التطبيق (App Launcher Icons)
يقوم الأمر التالي بقراءة إعدادات `flutter_launcher_icons` في `pubspec.yaml` وتوليد كافة مقاسات الأيقونات المطلوبة لأندرويد و iOS تلقائياً:
```bash
dart run flutter_launcher_icons
```

### ب. توليد شاشة البداية الأصلية (Native Splash Screen)
يقوم الأمر التالي بقراءة إعدادات `flutter_native_splash` في `pubspec.yaml` وتوليد شاشات البداية المدمجة في النظامين:
```bash
dart run flutter_native_splash:create
```

## 3. خطوات الفحص والبناء البرمجي (Build Commands)

### الخطوة 1: تنزيل الحزم والمكتبات
لتثبيت كافة التبعيات البرمجية المعرفة في ملف `pubspec.yaml`:
```bash
cd mobile_app
flutter pub get
```

### الخطوة 2: الفحص الثابت للكود البرمجي (Static Analysis)
يجب تشغيل أداة التحليل لاكتشاف أي تحذيرات أو أخطاء برمجية في كود Dart ومعالجتها:
```bash
flutter analyze
```

### الخطوة 3: ضبط رابط الخادم المباشر للإنتاج
قبل بناء النسخة النهائية الموجهة للمتاجر، يجب تعديل عنوان الخادم في الملف:
`mobile_app/lib/core/constants/api_constants.dart`
وتغيير الرابط المحلي `http://10.0.2.2:3000` أو `http://localhost:3000` إلى رابط الخادم الحي المشفر عبر بروتوكول HTTPS، مثال:
```dart
static const String defaultBaseUrl = 'https://api.yourdomain.com';
```

### الخطوة 4: بناء نسخ نظام أندرويد (Android Builds)

- **بناء ملف APK للتثبيت المباشر والتجربة اليدوية على الأجهزة**:
  ```bash
  flutter build apk --release
  ```
  المسار الناتج للملف:
  `build/app/outputs/flutter-apk/app-release.apk`

- **بناء حزمة Android App Bundle المخصصة لمتجر Google Play Console**:
  ```bash
  flutter build appbundle --release
  ```
  المسار الناتج للملف:
  `build/app/outputs/bundle/release/app-release.aab`

### الخطوة 5: بناء حزمة نظام أبل iOS (تنفذ على جهاز ماك فقط)

- **تحديث مكتبات البودز (CocoaPods)**:
  ```bash
  cd ios
  pod install
  cd ..
  ```

- **بناء أرشيف IPA لمتجر App Store Connect**:
  ```bash
  flutter build ipa --release
  ```
  المسار الناتج للأرشيف:
  `build/ios/archive/Runner.xcarchive`
  أو ملف التثبيت:
  `build/ios/ipa/*.ipa`

- **الرفع إلى TestFlight أو متجر التطبيقات**:
  يتم الرفع عبر أداة `Transporter` على نظام ماك أو مباشرة من داخل برنامج `Xcode` عبر قائمة `Organizer` بعد تحديد الحساب والشهادات الرقمية المعتمدة.

## 4. قائمة الفحص والاختبار اليدوي على جهاز حقيقي قبل الرفع

يجب تثبيت ملف `app-release.apk` (على أندرويد) أو تجربة نسخة `TestFlight` (على آيفون) والتحقق من العمليات الحيوية التالية:

### 1. تسجيل الدخول والتوثيق (Authentication)
- تسجيل الدخول السريع برقم الهاتف وكود المشترك عبر المسار `/api/v1/auth/login-fast`.
- التحقق من حفظ التوكن في التخزين المحلي واستعادة الجلسة عند إغلاق التطبيق وإعادة فتحه.
- التحقق من وجود وتفعيل بوابة التحقق من السن (Age Gate) في الشاشة.

### 2. ظهور واستعراض الخطة التدريبية والغذائية (Plan Retrieval)
- جلب بيانات البرنامج النشط من الخادم `/api/v1/programs/active`.
- التحقق من عرض تفاصيل التمارين (المجموعات، التكرارات، فترات الراحة، شارات البدائل) كدليل استرشادي ثابت وخالٍ تماماً من جداول تسجيل الجولات الفردية أو المؤقتات.
- التحقق من تفاصيل الوجبات والماكروز اليومية والمكملات الغذائية، وعدم وجود أي قوائم تسوق سوبرماركت.

### 3. تسجيل التمرين المنجز (Workout Logging)
- فتح بطاقة تسجيل التمرين الذكية وتدوين الوزن وعدات آخر مجموعة والجهد المبذول.
- إرسال السجل بنجاح عبر المسار `/api/v1/checkin/workout-logs`.
- التحقق من تخزين السجل في وضع عدم الاتصال (Offline Queue) في حال انقطاع الشبكة وإرساله تلقائياً عند عودة الاتصال.

### 4. إرسال استمارة المتابعة الأسبوعية (Weekly Check-in Submission)
- إدخال الوزن ومحيط الخصر ومستوى الطاقة والالتزام.
- التقاط أو رفع الصور التقييمية والتأكد من إرسالها إلى مسار الرفع المشفر `/api/v1/photos/upload`.
- إرسال استمارة المتابعة عبر `/api/v1/checkin` والتأكد من ظهور رسالة النجاح وانتقال الخطة لحالة الانتظار.

### 5. التحقق من آلية حذف الحساب (Account Deletion Verification)
- الدخول إلى شاشة الملف الشخصي والإعدادات.
- الضغط على زر حذف الحساب والتأكد من طلب التأكيد وإرسال الطلب لمسار الخادم `/api/v1/auth/delete-account`.
- التأكد من مسح بيانات الجلسة بالكامل وإعادة المتدرب لشاشة الدخول.
